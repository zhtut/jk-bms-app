# 极空（JK）BMS 电脑端监控程序 — 技术方案

> 项目代号：`jk_bms_app` · Flutter 桌面 + Web · 只读监控（不含 BMS 控制）
> 目标平台：Windows / macOS / Linux / Web(Chrome/Edge)
> 撰写日期：2026-10 · 基于对 `syssi/esphome-jk-bms`（事实标准协议参考实现）源码的逐行分析

---

## 1. 背景与关键结论

### 1.1 为什么 better-bms-app 读到的是错误数据

实测：用 [encap/better-bms-app](https://github.com/encap/better-bms-app)（Web Bluetooth）能连上设备，但数据全错。

原因（本项目调研的核心结论）：**极空 BMS 的 BLE 协议存在两代帧格式 + 三种帧变体**：

| 协议 | 帧头 | 特征 | 典型设备 |
|---|---|---|---|
| 旧协议（UART 风格） | `4E 57`（"NW"） | 寄存器流（TLV：寄存器地址+类型+长度+数据），XOR 校验，帧尾 `68 38` | 老固件走串口/部分老蓝牙板 |
| **新协议（当前主流）** | `55 AA EB 90` | 固定 **300 字节大帧**，按帧类型+绝对字节偏移解析，求和校验（sum mod 256） | 现行固件的 BLE 通道，**储能系列（JK-PB/Inverter BMS）即此协议** |

新协议又分 3 个帧变体（**寄存器偏移互不兼容**）：

- `JK02_24S` — 最多 24 串，电芯电压 u16（mV）
- `JK02_32S` — 最多 32 串，字段整体后移 16/32 字节，**PB 系列储能板属于此类**（实测样例：`JK_PB2A16S15P`，硬件 `14.XA`，软件 `14.20`）
- `JK04` — 新款（如 JK-B2A16S v3），电芯电压为 IEEE754 float32

better-bms-app 按旧协议/单一变体解析新协议的字节流 → 偏移全部错位 → "能连上但数据全错"。

### 1.2 本方案的对应对策

1. **实现新协议全部 3 个帧变体**，逐字节移植 esphome-jk-bms（main 分支）的解码表；
2. **自动探测变体**：根据电芯电压合理性（float 区间 / u16 mV 区间 / 总压一致性 / SOC≤100 等多因子打分）自动判定 JK04 / JK02_24S / JK02_32S；
3. **手动覆盖**：设备页可强制指定变体（应对特殊固件）；
4. **原始帧调试页**：完整记录收发的每一帧 hex，方便日后对照官方 App 继续逆向未解析字段。

### 1.3 协议要点速查（新协议）

**GATT**
- 服务 UUID：`0xFFE0`；特征 UUID：`0xFFE1`
- 新蓝牙模块（MAC `20:21:11:xx`）：handle 3 = 写命令，handle 5 = 通知（另有 0x2902 描述符）
- 旧蓝牙模块（MAC `C8:47:8C:xx`）：单个 FFE1 特征同时具备写+通知
- 选择特征时**按属性**（notify / write|writeWithoutResponse）匹配，不硬编码 handle

**命令帧（App → BMS，20 字节）**

```
偏移  内容
0-3   AA 55 90 EB          帧头
4     命令字                0x96=请求电芯信息帧  0x97=请求设备信息帧  0xA1=请求日志帧
5     值长度（0）
6-9   值（u32 LE，0）
10-18 0
19    CRC = sum(byte[0..18]) mod 256
```

**响应帧（BMS → App，300 字节，BLE 分包到达需重组）**

```
0-3   55 AA EB 90          帧头（收到新帧头即清空残留缓冲）
4     帧类型                0x01=参数设置  0x02=电芯信息  0x03=设备信息  0x05=日志
5     帧计数
6-298 数据（按帧类型+变体的绝对偏移解析）
299   CRC = sum(byte[0..298]) mod 256（部分设备帧长 320，CRC 仍在 299）
```

**交互流程**

1. 连接 → 发现服务 → 订阅 FFE1 通知；
2. 发送 `0x97`（设备信息）→ 发送 `0x96`（电芯信息）；
3. BMS 周期性推送 `0x02` 电芯信息帧（约 0.5~2s/帧，取决于固件），无需轮询；
4. 若 2.5s 未收到数据帧则重发 `0x96`（重试上限 12 次）；运行中断流 >15s 触发看门狗重发。

**电芯信息帧（0x02）关键偏移**

- JK02（o1=0/16，o2=0/32 分别为 24S/32S 的偏移）：
  - `6+2i`：电芯电压 u16 mV；`64+o1+2i`：电芯内阻 u16 mΩ
  - `118+o2`：总压 u32 mV；`126+o2`：电流 i32 mA（**正=充电，负=放电**；功率=总压×电流，不用 122 处的无符号功率字段）
  - `130/132+o2`：温度1/2 i16 0.1°C；`134+o2`：24S=MOS温度 / 32S=告警位掩码 u32（LE）；24S 告警位掩码在 `136` (u16)
  - `138+o2`：均衡电流 i16 mA；`140+o2`：均衡动作(0无/1充均衡/2放均衡)；`141+o2`：SOC %
  - `142/146+o2`：剩余/标称容量 u32 mAh；`150+o2`：循环次数；`158+o2`：SOH %
  - `162+o2`：累计运行秒数；`166/167+o2`：充电/放电 MOS 状态；`168`：预充；`169`：均衡中
  - `182+o2`：温度传感器缺失位掩码（bit0=MOS,bit1..5=传感器1..5 → 对应温度显示为无效）
  - `183+o2`：加热；`204+o2`：加热电流 i16 mA；`213+o2`：充电器插入
  - 仅 32S：`222/224/226+o2`：温度5/4/3；`243+o2`：电池类型(0=LFP/1=三元/2=LTO)；`246+o2`：充电阶段时长；`248+o2`：充电阶段(0恒流/1恒压/2浮充)；`249+o2`：干接点(bit1=DRY1,bit2=DRY2)
- JK04：`6+4i` 电芯电压 float32 V；`102+4i` 内阻 float32 Ω；`202` 平均电压；`206` 压差；`220` 均衡动作；`222` 均衡电流 float32；`286` 运行秒数 u32。（电流/温度/SOC 等字段社区尚未完全逆向 → 调试页保留原始帧供后续补齐）

**告警位掩码（32 bit，JK02）**：bit0 线阻异常 / bit1 MOS过温 / bit2 电芯数不符 / bit4 已充满 / bit5 电池组过压 / bit6 充电过流 / bit7 充电短路 / bit8 充电过温 / bit9 充电低温 / bit10 协处理器通信异常 / bit11 电芯欠压 / bit12 电池组欠压 / bit13 放电过流 / bit14 放电短路 / bit15 放电过温 / bit16 充电MOS异常 / bit17 放电MOS异常 / …（完整 32 项见 `lib/protocol/errors.dart`）

**设备信息帧（0x03）**：型号@6(16B) / 硬件版本@22(8B) / 软件版本@30(8B) / 开机时长@38(u32 s) / 上电次数@42 / 设备名@46(16B) / 生产日期@78(6B,YYMMDD) / 序列号@86(11B) —— ASCII，`\0` 结尾。

**参数帧（0x01，JK02，只读展示）**：电芯 OVP/UVP 及恢复值、充/放电过流与延时、温度保护组、均衡启动/压差/最大电流、串数、充/放/均衡开关、标称容量、32 路线阻、设备地址、加热启停温度、控制位掩码等（全部 u32×0.001/×0.1 定标）；JK04 为 float32 布局（已解析字段较少）。

**日志帧（0x05）**：条数@6(u32)，每条 5 字节：时间戳 u32（设备相对时间，秒）+ 事件码 u8（0x01 开机 … 0x64~0x83 电芯NN过充保护，0xC8~0xE7 电芯NN过放保护，全表见 errors.dart）。

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | **Flutter 3.47 stable** | 一套代码 → Windows/macOS/Linux/Web；用户已定 |
| BLE | **flutter_blue_plus 2.3.14**（+ `flutter_blue_plus_winrt`） | 唯一同时覆盖 Win/mac/Linux/Web(Web Bluetooth) 的成熟插件；2.x Windows 走 WinRT。个人用途适用其 nonprofit 许可（免费）。⚠️ 若将来商用需购买其商业授权 |
| 状态管理 | `provider` + `ChangeNotifier` | 单设备监控场景足够，避免过度设计 |
| 图表 | `fl_chart 1.3` | 纯 Dart，四端一致，趋势曲线 |
| 窗口 | `window_manager` | 桌面端设置标题/最小尺寸（Web 自动跳过） |
| 导出 | `file_selector` + `path_provider` | 历史数据 CSV 导出 |
| 自绘控件 | CustomPainter | 电池电量表、电芯电压条形图（还原极空 App 观感，零图片资源） |

**Web 端限制**（Web Bluetooth 平台特性，需在文档中告知用户）：
- 仅 Chrome / Edge / Opera（Firefox/Safari 不支持 Web Bluetooth）；
- 必须 `https://` 或 `localhost` 环境；
- 扫描走浏览器原生设备选择弹窗（按服务 UUID `FFE0` 过滤），无法后台自动重连受限；
- 不支持读 RSSI / 设置 MTU（对功能无影响，帧重组层已处理分包）。

**协议层为纯 Dart（零插件依赖）→ 可用 esphome 源码注释中的真实抓包帧做单元测试。**

**目录结构**

```
lib/
├─ main.dart / app.dart          # 入口、窗口设置、主题、路由壳
├─ models.dart                   # JkSnapshot / JkDeviceInfo / JkSettings / JkLogEntry / 枚举

│  └─ errors.dart                # 告警位表 / 日志事件表（中英）
├─ services/
│  ├─ ble_service.dart           # BLE 连接封装
│  ├─ bms_client.dart            # 会话编排：握手、重试、看门狗、事件流
│  └─ history.dart               # 历史环形缓冲 + CSV
├─ state/app_controller.dart     # 全局状态（含断线自动重连）
└─ ui/
   ├─ home_shell.dart            # NavigationRail(宽)/NavigationBar(窄) + IndexedStack
   ├─ pages/…                    # 7 个页面
   └─ widgets/…                  # 自绘仪表/条形图/卡片/指示灯
test/protocol_test.dart          # CRC/组帧/变体探测/三种解码器（真实抓包 fixture）
```

**关键健壮性设计**

- **分包重组**：300 字节帧经 BLE 通知分 15~20 包到达；组装器按帧头对齐 + CRC 校验，坏帧滑动 4 字节重扫，缓冲上限 4KB 防泄漏；
- **变体探测多因子打分**：float 合理性 → JK04；u16 mV 合理性 + 使能位掩码连续性 + 总压≈Σ电芯 + SOC/SOH≤100 → 24S/32S 择优；探测结果粘滞，可手动覆盖；
- **断线自动重连**：指数退避（1/2/5/10s），默认开启，可关；
- **温度传感器缺失掩码**：按 bit 置 null，UI 显示 `--` 而非假数据；
- **只读安全**：v1 不实现任何写寄存器（无 MOS 开关/参数修改/固件操作），从根上规避写坏电池组的风险。

## 4. UI 设计（对齐极空官方 App）

**风格**：浅色底 `#F2F4F8`、白色圆角卡片、蓝色主色 `#1E88E5`（官方 App 蓝）、充电绿/放电橙/告警红；顶栏蓝底白字显示设备名+连接状态。支持系统深色模式。

**页面**（宽屏左侧导航栏 / 窄屏底部导航）：

1. **连接**：扫描列表（名称/MAC/RSSI）、蓝牙状态提示、Web 浏览器弹窗引导、连接失败排查帮助（如"先断开手机 App——BMS 通常只允许一个 BLE 连接"）；
2. **监控**（主页面，仿官方"电池数据"页）：
   - 告警横幅（正常=绿色"系统正常"，异常=红色滚动列表）
   - 大号电池图形 + SOC% + 充/放电状态与功率
   - 指标卡网格：电池电压 / 电池电流 / 电池功率 / 均衡电流 / 剩余容量 / 循环次数
   - 电芯电压条形图（编号+mV 标注，最高红/最低蓝，平均虚线，压差徽标）
   - 温度组（传感器1~5 / MOS / 加热电流）
   - 状态灯组（充电MOS / 放电MOS / 均衡 / 加热 / 预充 / 干接点）
   - 电池信息（SOH/标称容量/循环容量/运行时间/电池类型/充电阶段）
   - 趋势图（电压/电流/功率/SOC/温度 可切换，最近 1 小时）
3. **电芯**：大条形图 + 每串明细表（电压/内阻/偏离均值 mV，超差高亮）；
4. **告警**：当前告警位列表 + 设备日志（0xA1 拉取，含"电芯NN过充保护"等 200+ 事件码中文对照）；
5. **参数**：只读展示保护参数（过压/欠压/过流/温度/均衡/容量/开关），顶部注明"监控模式，不提供修改"；
6. **设备**：型号/软硬件版本/序列号/生产日期/开机时长/上电次数 + 协议变体（自动/手动覆盖）+ 历史 CSV 导出 + 自动重连开关；
7. **调试**：原始帧收发日志（时间/类型/300 字节 hex 折行），供比对官方 App 与后续逆向 JK04 未知字段。

## 5. 平台构建与注意事项

| 平台 | 构建命令 | 注意事项 |
|---|---|---|
| Windows | `flutter build windows --release` | 需 VS2022 C++ 工作负载（已具备）；fbp 2.x 依赖 `flutter_blue_plus_winrt`（已加入）；系统需 BLE 4.0+ 适配器 |
| macOS | `flutter build macos` | 需在 `DebugProfile.entitlements`/`Release.entitlements` 添加 `com.apple.deviceusage.bluetooth.always`，Info.plist 添加蓝牙用途说明（本项目已配置） |
| Linux | `flutter build linux` | 运行时依赖 BlueZ；发行版需 `bluez` 服务 |
| Web | `flutter build web` | 部署需 HTTPS（或 localhost 调试）；仅 Chrome/Edge；扫描为浏览器弹窗选设备 |

**测试策略**：协议层单测使用 esphome-jk-bms 源码注释中的**真实设备抓包帧**（JK02_32S 电芯帧、JK04 电芯帧、设备信息帧）作为 fixture，断言 CRC、变体探测与解码值；组帧器测试覆盖分包/脏数据/粘帧/超长帧场景。真机联调清单见 README。

**里程碑**
- M1（本次交付）：协议层 + 连接层 + 监控/电芯/告警/参数/设备/调试全页面 + 单测通过 + Windows/Web 构建通过
- M2（后续可选）：JK04 缺失字段逆向（借助调试页抓帧比对官方 App）、历史数据 SQLite 持久化、多语言、MQTT 上报
- M3（明确不做/暂缓）：写控制（MOS 开关、参数下发）、固件升级 —— 风险高，待只读稳定运行后再评估

## 6. 风险清单
